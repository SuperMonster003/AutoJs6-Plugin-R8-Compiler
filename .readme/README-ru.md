### Введение

******

Скрипты AutoJs6 могут загружать JAR через `runtime.loadJar()` и вызывать содержащиеся в нём классы Java. Этот путь по умолчанию использует D8 для простой компиляции JAR в DEX, без сжатия и обфускации. Когда вам нужно, чтобы результат прошёл полную release-обработку -- удаление неиспользуемого кода (shrinking), оптимизацию байткода и обфускацию идентификаторов -- нужен R8.

Этот плагин -- отдельно устанавливаемое приложение, которое запускает закреплённую версию компилятора Google R8 в собственном изолированном процессе, предоставляя AutoJs6 явный сервис полной release-компиляции. Скрипты запускают компиляцию через специальную точку входа `runtime.loadJarWithR8()` и обязаны передать keep-правила; AutoJs6 получает обратно пять артефактов (DEX, mapping и другие), проверяет каждый, кэширует их и загружает только проверенный DEX.

Главное отличие от встроенного пути: точка входа R8 явная и без отката. Неудачная компиляция никогда не переключается втихую на D8/dx; ошибка возвращается скрипту как есть. Это гарантирует простой инвариант: если загрузка удалась, артефакт прошёл полную обработку R8.

Когда стоит установить этот плагин: нужно уменьшить или обфусцировать JAR-артефакт; нужны файлы mapping для последующей деобфускации трассировок стека; или нужна полностью детерминированная семантика компиляции (либо полный R8, либо явный сбой).

### Как это работает

******

При включённом плагине один вызов `runtime.loadJarWithR8()` проходит примерно следующие шаги:

```text
1. script     calls runtime.loadJarWithR8(program, keepRules[, classpath[, consumerRules, ordinals]])
2. AutoJs6    snapshots program, classpath and rule files into one canonical path-free input bundle
3. plugin     re-verifies the bundle, then runs pinned R8 (full release profile) in its private ":r8" process
4. plugin     streams back one bundle with five artifacts: DEX ZIP, mapping, seeds, usage, retrace metadata
5. AutoJs6    re-validates every artifact, commits an R8-only cache generation, and loads the verified DEX ZIP
*  no fallback: any failure terminates the call as an R8 error; D8/dx is never used silently
```

Плагин отвечает только за шаги 3 и 4 -- за саму компиляцию; снимок и фиксация входных данных, проверка артефактов, кэширование и финальная загрузка классов всегда выполняются AutoJs6. Стороны обмениваются через Binder только файловыми дескрипторами, пути к файлам никогда не передаются по каналу, и плагин не может читать каталог ваших скриптов. Результаты кэшируются по содержимому входа и параметрам компиляции в выделенном кэш-домене R8; повторные загрузки того же входа попадают прямо в кэш, повреждённые данные кэша автоматически вытесняются и перекомпилируются, а каждый артефакт, открываемый из кэша, сначала заново хэшируется.

******

### Функции

******

- Полная release-компиляция: shrinking (удаление неиспользуемого кода), оптимизация и обфускация всегда включены все вместе и выполняются закреплённым R8 8.13.17.
- Явная семантика без тихого отката: этот плагин использует только `runtime.loadJarWithR8()`; любой сбой завершается ошибкой R8 и никогда не переключается втихую на D8/dx. `runtime.loadJar()` и `runtime.loadJarWithClasspath()` остаются полностью неизменными.
- Пять артефактов за один обмен: DEX ZIP, mapping (карта обфускации), seeds (сохранённые элементы), usage (удалённые элементы) и метаданные retrace; каждый привязан к SHA-256 и независимо перепроверяется хостом.
- Компиляция выполняется в собственном процессе `:r8` плагина и в приватном рабочем пространстве, изолированно от AutoJs6; вход полностью перепроверяется перед запуском R8.
- Поддерживаются упорядоченные classpath-JAR времени компиляции и consumer-правила, привязанные к своему classpath-JAR; keep-правила должны передаваться явно, правила никогда не обнаруживаются неявно внутри архивов.
- В комплекте байт-верифицированная платформенная библиотека Android 36 в качестве библиотеки компилятора -- вместо зависимости от возможно урезанных JAR boot classpath устройства; `minApi` компилятора от 24 до 36 полностью покрыт реальным корпусом R8.
- Поддерживается Android 7.0 (API 24) и выше; проверено на физических устройствах и эмуляторах API 25/28/37 (включая устройство со страницами 16 KiB) с реальным исполнением на ART, вызовами JNI и восстановлением через Retrace.
- Общается только с AutoJs6 с той же подписью (защищено разрешением `org.autojs.permission.PLUGIN`) и не запрашивает разрешений на сеть или хранилище.

### Связь с плагином DEX Compiler

******

В экосистеме AutoJs6 есть два независимых плагина-компилятора. Они дополняют друг друга, не пересекаются и могут быть установлены одновременно:

- [AutoJs6-Plugin-DEX-Compiler](https://github.com/SuperMonster003/AutoJs6-Plugin-DEX-Compiler) обслуживает путь по умолчанию `runtime.loadJar()` / `runtime.loadJarWithClasspath()`: простая компиляция более новым D8, без сжатия и обфускации; при сбое плагина хост автоматически откатывается на встроенный компилятор.
- Этот плагин (R8) обслуживает только явный путь `runtime.loadJarWithR8()`: полная release-компиляция с обязательными keep-правилами; сбой остаётся сбоем, без отката.

Оба используют полностью независимые протоколы (`dex-compiler-api` и `r8-compiler-api`), действия сервисов, пункты параметров разработчика и кэш-домены; ни один не зависит от другого и не знает о нём. Режим `RELEASE` в протоколе DEX -- это просто release-режим компиляции D8, не имеющий отношения к R8. Установка или удаление любого из них никогда не влияет на другой.

### Установка и использование

******

Включение плагина занимает три шага: установить парную сборку AutoJs6 с интеграцией R8, установить APK этого плагина, затем вручную выбрать плагин в параметрах разработчика AutoJs6. Два момента, которые стоит знать заранее:

- Плагин по умолчанию бездействует. Сама по себе установка ничего не меняет в AutoJs6; пока он не включён, `runtime.loadJarWithR8()` просто безопасно завершается сбоем (fail-closed), а не использует другой компилятор.
- Всё обратимо. Отключите пункт в параметрах разработчика, чтобы вернуть прежнее состояние; удалять ничего не нужно.

#### Предварительные условия

- Сборка AutoJs6 с интеграцией `runtime.loadJarWithR8()` (репрезентативная проверенная сборка: AutoJs6 6.8.0 (build 5276)); в более старых хостах нет ни точки входа, ни соответствующего пункта параметров разработчика.
- Хост и плагин должны происходить из одного доверенного источника и иметь одинаковую подпись; при несовпадении подписей плагин нельзя выбрать -- используйте установочные пакеты, выпущенные (или собранные) парой.
- Плагин сейчас находится на стадии закрытого предварительного выпуска; установочные файлы берутся из закрытого предрелиза GitHub или локальной сборки. Получайте их вместе с парным хостом.
- При самостоятельной сборке не меняйте фиксированные имя пакета и компонент сервиса, указанные ниже.

Соответствующие идентификаторы:

```text
host package: org.autojs.autojs6
plugin package: io.github.supermonster003.autojs6.plugin.r8compiler
paired host: AutoJs6 6.8.0 (build 5276)
exact component: io.github.supermonster003.autojs6.plugin.r8compiler/io.github.supermonster003.autojs6.plugin.r8compiler.R8CompilerService
```

#### Установка и включение

1. Установите или обновитесь до парной сборки AutoJs6 с интеграцией R8.
2. Установите APK этого плагина.
3. Откройте AutoJs6, перейдите в Настройки > О приложении и разработчике и удерживайте значок приложения, чтобы войти в параметры разработчика.
4. Перейдите в R8 compiler > Explicit full-release R8 provider.
5. Выберите компонент сервиса этого плагина (exact component, указанный выше) и подтвердите.

Повторим: сама установка никогда не включает плагин, и AutoJs6 никогда не выбирает автоматически ни один обнаруженный provider; пока выбор не сделан, `runtime.loadJarWithR8()` всегда завершается сбоем.

#### Проверка активации

Вернувшись на страницу параметров разработчика: настройка удалась, когда сводка Explicit full-release R8 provider сообщает, что `runtime.loadJarWithR8` использует компонент этого плагина; сводка со словами «disabled» или «fails closed» означает, что точка входа всё ещё выключена.

Если плагин не появляется в списке, проверьте по порядку: хост -- парная сборка с интеграцией R8; имена пакетов хоста и плагина совпадают с идентификаторами выше; приложение плагина не отключено системой; обе подписи совпадают.

В отличие от плагина DEX, у этой точки входа нет неоднозначности «кто на самом деле компилировал»: если `runtime.loadJarWithR8()` вернулся успешно, артефакт обязательно прошёл полную обработку R8 (в этом вызове или в ранее проверенном поколении кэша).

#### Пример скрипта

Поместите JAR с файлами `.class` JVM и файл keep-правил в каталог скриптов, затем вызовите любую перегрузку семейства точек входа. Keep-правила не опциональны: R8 удаляет и обфусцирует каждый символ, не сохранённый правилом, поэтому компиляция без правил почти наверняка даст классы, к которым больше нельзя обратиться по исходным именам.

```javascript
"use strict";

const program = files.path("./lib/example.jar");
const keepRules = files.path("./lib/keep-rules.pro");

// keep-rules.pro (UTF-8), e.g.:
//   -keep class com.example.autojs6.R8PluginExample { public *; }

runtime.loadJarWithR8(program, [keepRules]);

// Replace this with a public class that actually exists in example.jar
// and is kept by your keep rules.
const Example = Packages.com.example.autojs6.R8PluginExample;
console.log("R8 compiler example: " + Example.answer());
```

Когда JAR программы ссылается на классы времени компиляции, которых нет внутри него (например, API-заглушки), используйте перегрузку с тремя аргументами и упорядоченным classpath:

```javascript
runtime.loadJarWithR8(
    files.path("./lib/program.jar"),
    [files.path("./lib/keep-rules.pro")],
    [files.path("./lib/compile-api-stubs.jar")],
);
```

Перегрузка с пятью аргументами дополнительно принимает файлы consumer-правил и их порядковые номера владельцев; каждый файл consumer-правил привязывается номером к соответствующему classpath-JAR:

```javascript
runtime.loadJarWithR8(program, keepRuleFiles, classpathJars, consumerRuleFiles, ownerOrdinals);
```

Ключевые моменты:

- Classpath-JAR используются только для разрешения ссылок при компиляции; они не упаковываются в выход и не загружаются автоматически. Их порядок значим и входит в идентичность кэша.
- Keep- и consumer-правила должны быть строгим текстом UTF-8; правила с доступом к файловой системе, include, перенаправлением ввода/вывода, словарями и подобными опасными директивами отклоняются сразу (fail-closed).
- Mapping и остальные артефакты сейчас проверяются и хранятся в приватном кэше хоста; экспортной точки входа для скриптов пока нет (см. ROADMAP).
- Компиляция -- не проверка безопасности; загружайте только JAR, которым доверяете.

#### Руководство по keep-правилам

Минимальные рецепты для доступа через `Packages`, рефлексии, JNI, сериализации и публичного API приведены в [практическом руководстве по keep-правилам](https://github.com/SuperMonster003/AutoJs6-Plugin-R8-Compiler/blob/master/docs/keep-rules-guide.md).

#### Что происходит при сбое

Семантика сбоя этой точки входа намеренно проста: вы получаете либо полные артефакты R8, либо ошибку -- ничего промежуточного.

- Provider не выбран, неверные аргументы, provider недоступен или занят (BUSY; одновременно допускается только один сеанс компиляции), сбой компиляции, тайм-аут (по умолчанию 120 с, максимум 300 с), сбой проверки артефактов, сбой кэша или загрузки -- всё это завершает вызов скрипта ошибкой R8, но никогда переключением на D8/dx.
- Ваша собственная отмена (например, остановка скрипта) немедленно завершает вызов и точно так же не вызывает отката.
- Попадание в кэш не меняет семантику: кэшированные артефакты были полностью проверены при записи и заново хэшируются при каждом чтении.

Если вам действительно нужно «при сбое откатиться на обычную компиляцию», перехватите ошибку в своём скрипте и явно вызовите `runtime.loadJar()`; хост не примет это решение за вас.

#### Диагностика и сообщения об ошибках

Самые частые причины по порядку: provider не выбран в параметрах разработчика; правила отклонены (запрещённые директивы или кодировка не UTF-8); вход превышает лимит ресурсов; имя класса написано с ошибкой или не покрыто keep-правилами (R8 обфусцировал или удалил несохранённые символы). При сообщении о проблеме приложите как можно больше из следующего:

- Версию и сборку AutoJs6, версию плагина и полное имя компонента из сводки параметров разработчика.
- Модель устройства, версию Android (API) и архитектуру CPU (ABI).
- JAR программы, вызвавший проблему, и все файлы правил (или их размеры в байтах и дайджесты SHA-256), полное исключение скрипта и шаги воспроизведения.

Если вы умеете пользоваться ADB, следующие команды соберут нужные журналы (замените `<serial>` на серийный номер вашего устройства; удалите приватные пути и чувствительное содержимое перед отправкой):

```powershell
adb -s <serial> shell dumpsys package org.autojs.autojs6
adb -s <serial> shell dumpsys package io.github.supermonster003.autojs6.plugin.r8compiler
adb -s <serial> logcat -d -v threadtime AndroidClassLoader:D AndroidRuntime:E *:S
```

#### Отключение, откат и удаление

- Временное отключение: выключите пункт Explicit full-release R8 provider в параметрах разработчика и подтвердите. `runtime.loadJarWithR8()` снова будет безопасно завершаться сбоем, больше ничего не изменится, а сохранённый выбор компонента можно в любой момент включить заново.
- Удаление плагина: сначала отключите точку входа, затем остановите AutoJs6 и удалите APK плагина. Удаление стирает все собственные данные и временные файлы плагина.
- После переустановки или обновления хост заново проверяет идентичность компонента (включая UID и подпись), поэтому выбор нужно подтвердить в параметрах разработчика ещё раз.

### Частые вопросы

******

**В: Почему keep-правила обязательны?**

О: Профиль full-release R8 удаляет и обфусцирует каждый символ, который не сохранён явно. Скрипты обращаются к классам рефлексивно через `Packages.xxx`, поэтому R8 не может вывести, какие символы должны уцелеть; протокол делает keep-правила явно обязательными, избегая тихой ловушки «скомпилировалось, но класс не найден».

**В: Это быстрее встроенного компилятора или плагина DEX?**

О: Нет -- обычно медленнее. R8 выполняет анализ всей программы (shrink/optimize/obfuscate), что по определению дороже простой компиляции D8; взамен вы получаете более компактный и трудный для реверса артефакт плюс файл mapping. Результаты кэшируются, так что последующие загрузки того же входа быстры.

**В: Может ли он заменить плагин DEX Compiler (или наоборот)?**

О: Нет. Они обслуживают разные точки входа скриптов с независимыми протоколами и кэшами; см. «Связь с плагином DEX Compiler».

**В: Почему нет автоматического отката на D8 при сбое?**

О: Так задумано. Вызов точки входа R8 -- это заявление «мне нужен полный release-артефакт»; тихий откат вручил бы вам необфусцированный артефакт без вашего ведома. Если нужна семантика отката, перехватите ошибку в скрипте и вызовите `runtime.loadJar()` сами.

**В: Как деобфусцировать трассировку стека?**

О: Каждая компиляция создаёт mapping и метаданные retrace, которые хост проверяет и кэширует; в текущей версии ещё нет точки входа для получения mapping из скрипта или интерфейса, а RPC retrace есть в плане развития. Когда вы собираете артефакт сами, используйте инструмент retrace из R8 с сохранённым mapping для восстановления стеков.

**В: Плагин выходит в сеть или читает мои файлы?**

О: Нет. У него нет разрешений на сеть и хранилище, вход компиляции он читает только из файловых дескрипторов, переданных AutoJs6, никогда не видит путей к файлам в канале и держит временные файлы строго в собственном приватном каталоге.

**В: Что делает интерфейс в лаунчере?**

О: Экран плагина только для чтения показывает версию плагина, закреплённую версию R8, доступность компонента сервиса и встроенный журнал изменений. Он не включает провайдер; выбор и активация по-прежнему выполняются только в параметрах разработчика AutoJs6.

### Границы возможностей

******

Во избежание недоразумений следующее явно находится вне области этого плагина:

- Обслуживает только `runtime.loadJarWithR8()`; никогда не меняет `runtime.loadJar()` и `runtime.loadJarWithClasspath()`, и эти точки входа не могут выбрать его неявно.
- Нет режима D8, нет debug-компиляции и нет отдельных переключателей shrink/optimize/obfuscate: профиль зафиксирован как FULL_RELEASE.
- Нет неявного обнаружения правил внутри JAR (например, proguard-файлов в META-INF); keep- и consumer-правила должны передаваться явно вместе с запросом.
- Правила с доступом к файловой системе, include, перенаправлением ввода/вывода, импортом mapping, print, словарями или директивами глобального управления профилем отклоняются (вне протокола 1.0, fail-closed).
- Нет RPC retrace; метаданные retrace -- только происхождение mapping, а экспорта mapping для скриптов пока нет (оба пункта в ROADMAP).
- Нет загрузки и разрешения зависимостей (нет интеграции Maven/Gradle), нет сетевой компиляции.
- Не обрабатывает `.aar`, предкомпилированные `.dex` и динамический байткод `defineClass()`; они всегда идут по встроенным путям AutoJs6.
- Пока только закрытое распространение: исходный код и установочные файлы находятся в закрытом репозитории GitHub; публичный выпуск -- отдельный пункт плана развития.

### Технический справочник

******

Следующее адресовано разработчикам и интеграторам, которым нужны точные границы; обычным пользователям плагина это обычно не нужно.

#### Ввод и вывод

Протокол 1.0 получает один канонический входной пакет через дескриптор только для чтения и возвращает один канонический пакет артефактов через дескриптор только для записи; пути к файлам никогда не передаются по каналу, а весь вход и каждый артефакт привязаны к SHA-256:

```text
input: 1 program JAR + ordered classpath JARs + explicit keep rules + optional consumer rules
output: DEX_ZIP + MAPPING_TEXT + SEEDS_TEXT + USAGE_TEXT + RETRACE_METADATA
compiler: R8 8.13.17
profile: FULL_RELEASE (shrink + optimize + obfuscate)
```

#### Идентификаторы обнаружения плагина

Хост обнаруживает и вызывает плагин по следующим идентификаторам:

```text
service action: org.autojs.plugin.R8_COMPILER
plugin id: r8-compiler
protocol provider id: autojs6-r8
engine: r8-compiler
variant: r8
protocol: 1.0–1.1
api namespace: org.autojs.plugin.r8compiler.api
distribution: org.autojs.plugin.r8compiler:r8-compiler-api:0.2.0
cache domain: autojs6:r8-compiler:v1
```

Плагин объявляет R8 8.13.17, протокол 1.0, фиксированный профиль FULL_RELEASE, `minApi` от 24 до 36, multi-dex-вывод и набор возможностей из пяти артефактов. Библиотека компилятора -- встроенная байт-верифицированная платформенная библиотека Android 36; отпечаток runtime-library по-прежнему привязан к наблюдаемым файлам boot classpath устройства.

Плагин не содержит нативных библиотек и покрывает все ABI устройств одним универсальным чисто-JVM APK; проверенные вызовы JNI относятся к нативным методам внутри компилируемых JAR, а не к самому плагину.

#### Модель безопасности

Плагин не запрашивает разрешений на сеть и хранилище. Сервис компиляции защищён разрешением `org.autojs.permission.PLUGIN` и работает в выделенном процессе `:r8`; каждый вызов проверяет имя пакета, UID вызывающего и обе подписи в обоих направлениях, принимая только хост AutoJs6 с той же подписью. Ввод и вывод передаются исключительно как файловые дескрипторы; дескрипторы с неверными режимами доступа или с вводом/выводом, указывающими на одну и ту же конечную точку, отклоняются. Временные файлы остаются в приватном рабочем пространстве плагина, а устаревшие пространства автоматически утилизируются. Хост также независимо перепроверяет каждый артефакт, а загрузчик классов принимает только заново хэшированную копию DEX, доступную только для чтения.

#### Лимиты ресурсов

Для защиты от вредоносного или аномального ввода протокол устанавливает жёсткие лимиты на каждом этапе; запросы сверх лимитов отклоняются сразу:

- JAR программы: до 128 MiB; classpath: до 32 JAR, по 64 MiB каждый, всего 128 MiB.
- Файлы правил: до 16 keep и 32 consumer; 256 KiB на файл, всего 2 MiB правил, 16 KiB на строку.
- Весь входной пакет до 260 MiB; развёртывание архива: до 20000 записей на JAR и 60000 всего, 512 MiB в распакованном виде; данные классов до 8 MiB на класс и 256 MiB всего.
- Выходной пакет до 256 MiB: DEX ZIP до 192 MiB, mapping до 32 MiB, seeds и usage до 16 MiB каждый, метаданные retrace до 256 KiB.
- Параллелизм: ровно один сеанс компиляции одновременно; остальные запросы получают повторяемый BUSY. Тайм-аут по умолчанию 120 с, потолок 300 с.
- Диагностика ограничена 64 KiB, пути в ней скрываются.

#### Предостережения

- `minApi` -- параметр компилятора, а не заявление об исполнении на устройстве; артефакт нельзя загрузить на устройствах ниже его `minApi`.
- Версия R8 закреплена (сейчас R8 8.13.17); идентичность кэша включает отпечатки компилятора и рантайма, поэтому обновление компилятора никогда не переиспользует устаревшие результаты.
- Отмена немедленно предотвращает публикацию результата, но внутренняя работа CPU в R8 может продолжаться в изолированном процессе до возврата компиляции; слот сеанса остаётся BUSY до завершения очистки.
- Один и тот же вход воспроизводится байт в байт при той же версии компилятора (release-гейты проверили воспроизводимость в одинаковой среде), но побайтовая идентичность между версиями R8 не обещается.
- Версия R8 из комплекта AGP, показываемая в баннере сборки хоста, относится к цепочке упаковки APK и не связана с версией компилятора этого плагина.

### Сборка

******

```powershell
.\gradlew.bat :app:assembleDebug
```

Релизная сборка:

```powershell
.\gradlew.bat :app:assembleRelease
```

Для сборки требуются JDK 17 или новее (рекомендуется 21) и Android SDK Platform 36: скрипт сборки байт-верифицирует `platforms/android-36/android.jar` и встраивает его как ресурс библиотеки компилятора, прерываясь при любом несоответствии. Текущий minSdk -- 24, targetSdk -- 36.

ABI протокола предоставляют замороженные контрактные AAR 0.1.0 внутри репозитория (в `plugin-api/r8-compiler-api/releases/0.1.0/`); приложение потребляет байты этих AAR, а не их исходные проекты:

```text
protocol-wire-api-0.1.0.aar
r8-compiler-api-0.2.0.aar
```

Компилятор берётся из Maven как закреплённый R8 8.13.17. Официальные выпуски используют скрипты публикации и проверки в `scripts/` (append-only локальный каталог выпусков, воспроизводимые сборки из двух снимков и погейтовая проверка); для повседневной отладки достаточно команд Gradle выше.
